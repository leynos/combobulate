# Combobulate initial language reference

Status: proposed API, revision 0.2. Date: 6 October 2026. Audience: users,
implementers, extension authors, and reviewers. Companions: `context.md`,
`technical-design.md`, and `roadmap.md`. Machine-readable table source:
`../spec/vocabulary.json`.

Decisions that control acceptance, with their authority, options, and status,
are recorded in the [decision register](decision-register.md).

No entry denotes a released or compiled implementation. The **Core** scope is
the initial numeric-language release boundary accepted in
[D03](decision-register.md#d03); the API within it remains proposed.
**Integration** entries belong to the explicitly gated typed-cell/segmented
workstreams. Their presence in this reference does not silently enlarge the
first release. Deferred proposals appear after the tables rather than
masquerading as available operations.

## 1. Reading the signatures and categories

`Unary` and `Binary` describe opaque operation handles. A signature describes
logical arguments, not a literal Rust trait signature. A configured operation,
such as `reshape([2, 3])`, produces a reusable unary descriptor. `.apply(...)`
is its ordinary Rust application interface; `comb!` supplies pipeline syntax.
Every sketch below describes proposed notation, not code compiled for this pack.

A **verb** operates on data. An **operator modifier** derives an operation from
one operation plus optional configuration. A **conjunction** combines multiple
operations; `fork` is a three-operand extension of that descriptive category.
**Policy modifiers** specialize an existing descriptor. These are project-local
categories, not a claim of exact APL grammatical compatibility. Macros
construct syntax and graphs; execution/extension interfaces are tabulated
separately.

All axis indices are zero-based. Numeric arrays default to identical-shape
agreement plus scalar extension. Typed cells remain atomic until `components`.
Binary mixed I64/F64 arithmetic requires a cast, except explicitly true `div`.
Bool counting needs `cast(I64)`. Each table contract inherits the detailed
rules in `technical-design.md` §§4-6 and `context.md`.

An unqualified aggregate such as `mean` consumes the whole current cell, across
all visible axes in row-major order. `reduce(add)` instead consumes the last
axis unless configured. A `.axis(...)` modifier on an aggregate restricts that
aggregate to the selected axis. Multi-axis numeric policies also specify the
order of flattening; the engine must not silently sort the axis list.

Examples preserve the established pipeline:

```rust
let centre = fork(identity, sub, mean);

let result = comb! {
    data
    |> cast(F64)
    |> rows(&centre)
    |> transpose
    |> rows(scan(add))
}.collect()?;
```

`centre` shares its input graph node. Borrowing `&centre` clones an operation
handle, not data. Construction can record semantic obligations without running
a kernel. `prepare` reports known failures; `execute` checks deferred
obligations.

The public proof API and staged-cost interfaces follow `technical-design.md`
§§17-19. Every row inherits proof-first delivery obligations appropriate to its
claim. A reference entry is not a proof result. Core includes public numeric
models/views, production sequential execution, and the certified static subset;
Integration adds domain cells, masks, segments, and sink proofs.

`comb!` remains the same frontend for statically described and dynamic graphs.
A static descriptor preserves facts for optional compile-time admission; it
does not permit evaluating arbitrary host configuration during compilation.
Strict cost policy rejects unresolved required bounds, while adaptive policy
keeps runtime checks. Neither mode labels estimates as hard guarantees.

## 9. Canonical notation and deliberate exclusions

`comb!` is the only pipeline DSL macro. `array!` and `arr!` are distinct
literal styles over one construction contract, not compatibility aliases.
`identity` is the canonical identity verb; `id` is not a parallel initial name.
`min` and `max` are binary verbs; `minimum` and `maximum` are aggregates.
`rank` /`rank2` are canonical; no separate `cells`/`cells2` alias family is
required.

`flow(f,g)` follows execution order; `compose(f,g)` follows mathematical
composition order. Both have explicit equations above. Left and right sections
use `.lhs(...)` and `.rhs(...)`; no second currying vocabulary is required.

Inside `comb!` or `verb!`, `==`, `!=`, `<`, `<=`, `>`, and `>=` lower to array
comparisons. `&`, `|`, and `!` express elementwise Boolean operations. Array
`&&` and `||` produce a syntax diagnostic explaining the distinction between
elementwise logic and guarded execution. Ordinary host Rust remains ordinary
Rust inside `host { ... }`.

The initial `verb!` form defines graph bodies. Kernel metadata belongs to
`native(kernel, schema)` and the extension registry, not a conflicting second
`verb!` grammar. Unknown calls do not cause the macro to guess whether a host
function is pure or traceable.

Deferred vocabulary includes FFT/decompositions, generic adaptive control flow,
GPU/JIT backends, complex/decimal dtype families, autodifferentiation,
arbitrary rank-changing column convenience rules, and distributed execution.
Full APL compatibility, mandatory array rewriting of geometry interiors, and
obsolete pre-1.0 source compatibility facades remain non-goals, not deferred
promises.

Public proof contracts specify successful outputs, success conditions, allowed
errors and mutation frames. Checked views and witnesses retain runtime safety
checks for ordinary callers. Library consumers can use exported logical models
and focused lemmas without accessing private graph or storage representation.

The actual callable, builder and execution bindings matter. A Kani/Verus
feature must not silently substitute a different executor; a passing reference
model is not a proof of Polars. Numerical accuracy, backend internals and
concurrent/SIMD routes retain separately reported evidence scopes. See the
[testable bets](testable-bets.md) for downstream acceptance and negative
controls.
